## POINT DE VÉRIFICATION 2 — purchase_course

### 2.1 Chemin complet avec lignes exactes

```
courses.py:317  → course = db.query(Course).filter(Course.id == course_id).first()
courses.py:321  → if not course.price or course.price <= 0: REJECT (gratuit)
courses.py:325  → existing = db.query(CoursePurchase)... (doublon check)
courses.py:334  → current_dt = get_dt_balance(db, current_user.id)
courses.py:335  → if current_dt < course.price: REJECT (402)
courses.py:343  → debit_dt(db, user_id, course.price)
    wallet.py:132  → current = get_dt_balance(db, user_id)  (2ème check)
    wallet.py:133  → if current < amount: raise InsufficientCreditsError
    wallet.py:138  → amount=-int(amount)  (truncation)
    wallet.py:142  → db.commit()  ← 1ER COMMIT (débit seul)
courses.py:348  → transaction = Transaction(...)  (pending)
courses.py:365  → purchase = CoursePurchase(...)  (pending)
courses.py:378  → enrollment = CourseEnrollment(...)  (pending)
courses.py:383  → db.commit()  ← 2ÈME COMMIT (ensemble)
```

### 2.2 Accès APRÈS confirmation du paiement

**✅ CORRIGÉ** — Ordre strict prouvé par le code :
1. `debit_dt()` à la ligne 343 — lève `InsufficientCreditsError` si échec
2. `CourseEnrollment` à la ligne 378 — seulement si `debit_dt` n'a pas levé d'exception
3. `db.commit()` à la ligne 383 — commit final

Aucun code path ne crée l'enrollment AVANT le débit. Le `try/except` aux lignes 342-345 empêche tout accès si le débit échoue.

### 2.3 Bugs détectés

**⚠️ Double commit non atomique :** `debit_dt()` commit au `wallet.py:142`. Si `courses.py:383` échoue ensuite, l'argent est débité sans enrollment ni purchase record.

**⚠️ Truncation integer :** `wallet.py:138` : `amount=-int(amount)`. Un cours à 14.99 TND débite 14 TND. Mais `courses.py:368` : `amount_paid=course.price` enregistre 14.99. Incohérence entre débit réel et montant enregistré.

### 2.4 Wallet IA vs wallet DT

**✅ SÉPARÉ** — Vérifié ligne par ligne :
- `purchase_course` appelle `debit_dt()` (ligne 343) → opère sur `WalletPool.DT_PURCHASED`
- Les crédits IA utilisent `WalletPool.AI_CREDITS` ou `user.ai_credits`
- `purchase_course` ne touche **jamais** `user.ai_credits`, `user.token_balance`, ou `user.dt_balance`
